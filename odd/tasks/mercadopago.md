## Specs

- **S1 — Connect from the admin.** "que el usuario vea en el admin una pantalla "integraciones" y que de a "conectar mercado pago" y pueda conectarse con la cuenta desde la que va a cobrar". Owner-only. OAuth authorization_code flow (`https://auth.mercadopago.com/authorization`, `POST https://api.mercadopago.com/oauth/token`) with `state` (CSRF) and PKCE S256. The screen shows the connected account and a "Desconectar" action. Connect/disconnect are written to `audit_logs` (entity `integration`).
- **S2 — "necesito que sea facil de usar".** The owner never copies keys. Errors (denied authorization, expired state, MP down) show a clear Spanish message on the Integraciones page.
- **S3 — Secrets at rest.** Access and refresh tokens are stored encrypted (AES-256-GCM, key from env), never logged or sent to the browser. Tokens are refreshed before expiry; MP rotates the refresh token on every refresh, so the new one is always saved.
- **S4 — "la idea es cobrar con mercado pago".** Checkout Pro **via the Orders API** (L8): on a `pending_payment` order the customer sees "Pagar con Mercado Pago"; the server creates an MP order (`POST /v1/orders`, `type: "online"`, `processing_mode: "manual"`, `external_reference` = order id, `config.online` return URLs + `auto_return: approved`, `expiration_time` = remaining reservation, cash types not allowed) with the seller token and redirects to `checkout_url`. Card data never touches Sublime. Shown only when MP is connected, payments are enabled and the order did not choose transfer.
- **S5 — Webhook.** `POST /api/mercadopago/webhook` (app-level webhook, event "Order (Mercado Pago)", `?data.id=ORD…&type=order`) validates `x-signature` (HMAC-SHA256 hex over `id:{data.id};request-id:{x-request-id};ts:{ts};` with the app's webhook secret), fetches the order from MP (`GET /v1/orders/{id}`), checks reference, paid amount and currency, and on `processed` calls the existing `confirmPayment` (actor `mercadopago`). Acceptance (auditoría v1.1): "aprobado, rechazado, duplicado, inválido, tardío y pendiente" all handled. Answers 200 for handled/duplicate/ignored, 401 for bad signature, 5xx on transient errors so MP retries.
- **S6 — Environment gating.** Works where configured (MERCADOPAGO_CLIENT_ID, MERCADOPAGO_CLIENT_SECRET, MERCADOPAGO_WEBHOOK_SECRET, PAYMENTS_ENCRYPTION_KEY); production also needs `SUBLIME_PAYMENTS_IN_PRODUCTION=enabled`. Without config the admin explains what is missing and checkout keeps the current manual flow. MP routes stay reachable during maintenance (proxy).
- **S6b — Direct token fallback (L11).** Optional `MERCADOPAGO_ACCESS_TOKEN` (test credentials in staging): when no account is connected by OAuth, checkout and webhook use it; an OAuth-connected account always wins. Integraciones shows "Conectada con credenciales del servidor" and still offers "Conectar Mercado Pago".
- **S7 — Docs.** Setup steps (create the MP application, redirect URL, webhook URL + secret, test users, PKCE), env vars, and test-mode → live checklist.
